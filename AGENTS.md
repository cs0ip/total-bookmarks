# Рекомендации по проекту

## Способ решения задач

Если какая-то задача не решается способом, который запросил пользователь, то не нужно искать обходные пути. Нужно остановиться и сказать пользователю о проблеме.

## Ограничения браузеров и сборки

- Общие WebExtension API вызывайте через `browser`: Chrome 148+ поддерживает этот namespace и Promise API нативно, дополнительный полифилл не нужен. Различия браузеров держите в `src/platform/`, не добавляйте их в компоненты интерфейса.
- Фоновые слушатели регистрируйте синхронно при загрузке, без отложенных import. DOM-зависимый загрузчик иконок не должен попадать в Chrome service worker.
- Валидатор AMO может предупреждать об `innerHTML` внутри Svelte runtime (`dom/reconciler.js`, `create_fragment_from_html`): он создаёт DOM из статических шаблонов компилятора. Не изменяйте runtime ради подавления предупреждения и не передавайте названия, URL закладок или переводы через `{@html}`.
- Firefox не реализует `onChildrenReordered`: даже обращение к нему должно исключаться из Firefox-пакета при сборке, иначе валидатор AMO выдаёт предупреждение.
- Сохраняйте явный CSP страницы расширения `script-src 'self'; object-src 'self';`, чтобы загрузка с HTTP-сайтов не повышалась автоматически до HTTPS.
- В `src/app.css` правило шрифта `body` должно оставаться вне `@layer`: Chrome добавляет собственные стили страниц расширений без слоя, перекрывающие utilities Tailwind. Размер корневого шрифта и масштаб браузера остаются пользовательскими.
- Ctrl+N зарезервирован Firefox (`key_newNavigator`, `reserved="true"`) и не перехватывается страницей; не назначайте его командам интерфейса.

## Изменение ресурсов и процесса сборки

- После изменения `public/icons/logo.svg` запустите `python3 scripts/export-logo.py` и обновите PNG в репозитории. Нужны системные librsvg, GdkPixbuf и GObject; обычная сборка PNG не пересоздаёт.
- При изменении инструментов или процесса сборки обновляйте обе английские инструкции в `docs/build/` и проверяйте воспроизводимость из распакованного исходного архива.

## Проверки

Команды сборки, упаковки, локальной установки и запуска тестов описаны в [README.md](README.md).

- Синтетические события клавиатуры в странице и действия WebDriver в content-контексте не подтверждают перехват зарезервированных сочетаний браузера. Для проверки конфликтов в Firefox используйте `EventUtils.synthesizeKey()` из окна браузера через chrome-контекст Marionette, как в `tests/run-site-icons.py`. Клавиатурные проверки Chrome внутри страницы также синтетические.
- Изменения фокуса и выбора языка проверяйте настоящими кликами: в Firefox микрозадачи могут выполняться до обновления `document.activeElement` при нативной передаче фокуса. В `focusout` переход внутри меню нужно определять по `relatedTarget`.

## Язык сообщений

- Все записи `console.*` и тексты создаваемых кодом исключений должны быть на английском языке.
- Пользовательские сообщения интерфейса переводятся на выбранный язык и не должны использоваться как текст логов. Пользовательские названия закладок и папок не переводятся.

## AGENTS.md и README.md

- В AGENTS.md записывайте только необходимые инструкции для разработки и неочевидные ограничения. Перед добавлением проверяйте, нельзя ли получить эти сведения из кода или существующей документации; если можно, не добавляйте их. Не пересказывайте устройство компонентов, алгоритмы, параметры, внешний вид интерфейса и состав тестов, не ведите здесь историю изменений и отчёты о выполненных задачах. Описания конкретной реализации, требующие обновления вслед за кодом, оставляйте в исходниках, а не в AGENTS.md.
- В README.md записывайте описание для пользователя и информацию по сборке и запуску. Не дополняйте его детальным описанием каждой новой функциональности.
